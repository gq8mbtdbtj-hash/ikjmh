# 风险评估 — 跨平台托盘版本中心

**状态：** 草案 v0.4  
**日期：** 2026-09-08  
**范围：** Spec + RFC-0001 的技术、产品、安全与交付风险（含**自更新**、**C++11**、**pthread/pthreads-w32**）  
**标度：** 可能性 × 影响 = **L**（1–5）× **I**（1–5）；**得分** = L×I

---

## 1. 摘要

最高风险为 **macOS 公证**、**自更新供应链 / 应用失败**、**远程 JSON 作为控制面**，以及**自更新范围膨胀成通用工具安装器**。若 v1 不引入 WebView 栈，体积目标仍可达成。

| 得分 | 级别 |
|-----:|------|
| 1–4 | 低 |
| 5–9 | 中 |
| 10–15 | 高 |
| 16–25 | 严重 |

## 3. 威胁模型（轻量）

**资产：** 用户机器完整性、**本应用安装树**、工具启动路径、配置真实性、托盘 UX 可用性。

**信任边界：**

```
[远程配置 + 更新清单] --HTTPS--> [HttpClient]
        |                              |
        v                              v
   [校验器] ----> [缓存]         [UpdateCoordinator]
        |                              |
        v                              v
 [面板动作]                    [SHA-256 校验 → 暂存]
        |                              |
        v                              v
 [打开 URL | path]          [更新助手 → 替换 → 重启]
```

**假设：**

- 若用户信任恶意 CA，配置 / 更新主机可能被攻破或中间人。
- 本机用户本就可改自己的安装；目标是不让远程失陷轻易变成完全沦陷。

**主要滥用：**

1. 恶意 JSON 打开钓鱼 URL。  
2. 恶意 `path` 动作。  
3. 未来 `command` 动作 → RCE。  
4. **恶意更新包**（被篡改的 zip）替换二进制。  
5. **清单指向攻击者 URL**，且哈希对应恶意软件（主机被控）。

**控制措施：** HTTPS、应用前 SHA-256、分发的应用与助手做 OS 代码签名/公证、禁止 shell 动作、自更新仅限本应用、优先版本化回滚目录、可选应用级 ed25519（P1）。

## 4. 平台风险说明

### Windows

- 资源管理器托盘怪癖、溢出区、DPI。
- 未签名主程序**与更新助手**易被杀软误报 — 两者都签名。
- 文件锁：替换前主 exe 必须退出（R23）。

### macOS

- Accessory 激活策略；刘海区域间距。
- 首次发布**与每次更新产物**都需要公证（R8）。
- 替换 `/Applications/*.app` 可能需要用户可写安装或明确失败（R24）。

### Linux（延后）

- AppIndicator vs StatusNotifier vs Wayland；仅作研究 spike。

## 5. 体积风险预算

| 组件 | 大致预算 |
|------|----------|
| 应用 + 平台 UI | 1–3 MB |
| RapidJSON（仅头文件） | ~0（编译期） |
| pthreads4w（Win 静态） | ~0.1–0.3 MB |
| HTTP（系统） | ~0 |
| 更新助手 | ≤ 0.5 MB（或同二进制加参数） |
| Zip/miniz（若需要） | ≤ 0.3 MB |
| 图标/资源 | < 0.5 MB |
| CRT / 静态库 | 1–4 MB |
| **余量** | 凑满 8–15 MB 上限前的剩余 |

**超标时的砍法：** 去掉崩溃上报；避免静态 curl+openssl；避免 ImGui；签名成本高时用同一二进制 `--apply-update` 代替独立助手。

---

## 6. 应急决策

| 触发条件 | 回退方案 |
|----------|----------|
| 某 OS 原生列表面板落后超过 1 周 | 该 OS 限时 Dear ImGui |
| C++ macOS 托盘进度失败 | Rust `tray-icon` spike；保留 C++ 核心 |
| 体积 > 15 MB | 去掉非系统 TLS；重审静态链接 |
| 安全评审禁止 `path` 动作 | 仅发 `url` + `none` |
| M7 前自更新应用仍不可靠 | 改为「下载 + 打开文件夹 / 打开 DMG」手工应用；仍做校验 |
| Zip 解压缺陷 | 小体积 Rust `cdylib` 解压+校验模块 |
| pthreads4w 与 MSVC CRT 冲突 | Win 改动态 pthread DLL；保持 pthread API 表面 |

---

## 7. 残余风险

**macOS 签名/公证**与 **Windows 文件替换竞态**是自更新最可能拖进度的项。**远程清单作为控制面**仍是最高安全残余风险 — 哈希 + OS 签名可缓解，无法消灭。范围不得静默膨胀为安装任意目录工具。

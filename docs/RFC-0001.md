# RFC-0001 — 架构：原生 C++ 托盘中心

**状态：** 提议中（rev 4 — C++11 + pthread/pthreads-w32 + 自更新）  
**作者：** 项目启动  
**日期：** 2026-09-08  
**依赖：** [SPEC.md](./SPEC.md)

---

## 1. 摘要

构建一款**托盘常驻的版本中心**：**C++11** 应用，薄平台后端 + 共享核心（配置、HTTP、缓存、模型、**自更新**）+ 轻量原生面板。**全平台并发统一使用 POSIX pthread API**；Windows 通过 **pthreads-w32**（现维护为 **pthreads4w**）提供实现，使 worker、互斥量、条件变量与 macOS/Linux 的 `libpthread` 源码兼容。v1 **默认**原生面板以控制包体积，避免 Electron/CEF；**Windows 可选**嵌入系统 **WebView2**（`panel_ui=webview`）加载远程现有前端，不打包 Chromium。业务与框架通过 **`IAppModule`（C++）/ `framework.Module`（Go）** 解耦：核心不写死产品菜单与业务 API。仅在实测有明显收益时，才以 C ABI 引入可选 **Rust** 模块。

**语言基线：** 共享 / 可移植代码仅用 ISO C++11。不要求 C++14/17/20 特性（如 `std::optional`、`std::filesystem`、`std::string_view`、结构化绑定、concepts 等）。平台 Objective-C++ / Win32 仅在不可避免时使用更新编译模式；公共头文件与 `core/` 保持 C++11。

**线程基线：** `core/` 与共享 worker 使用 `#include <pthread.h>` + `pthread_*`。可移植模块**不要**使用 `std::thread` / `std::mutex`（避免双运行时、统一心智模型）。UI / 消息泵线程仍为操作系统 UI 线程；pthread 负责后台工作，通过投递消息 / 线程安全队列回传 UI。

## 2. 动机

- Spec 要求跨平台托盘 + 面板 + JSON + HTTP，且**体积小**。
- 项目目录为 `tray_demo`；**不以 MFC / Qt / Electron 作为跨平台基础**。
- JetBrains Toolbox 仅作交互参考，不意味着交付 JVM/CEF 技术栈。

## 3. 决策驱动因素

1. 二进制体积与启动延迟  
2. 原生托盘 / 菜单保真度  
3. 快速、稳健的 JSON 解析  
4. 可维护的 Win + macOS 代码路径  
5. C++ 优先；Rust 其次  
6. 线程 API 跨平台复用（pthread）

## 4. 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| A. Electron / NW.js | UI 快 | 体积巨大、常驻 Chromium | 拒绝 |
| B. Tauri / Wry WebView | 小于 Electron | 仍是 WebView；系统 WebView 差异；偏 Rust | v1 **默认 UI** 拒绝 |
| B2. Win WebView2 嵌入远程站 | 复用现有前端；不打包 Chromium | 依赖 Evergreen Runtime；非跨平台 | **可选**（`panel_ui=webview`） |
| C. Qt Widgets | 成熟、跨平台 | 静态/动态体积大 | 因体积拒绝 |
| D. MFC + Win32 | 仅 Windows 成熟 | 无法覆盖 macOS/Linux | 不作主方案 |
| E. 纯 C++ 原生托盘 + 自定义/imgui 面板 | 最小、C++ 优先 | 平台代码更多 | **采纳（主方案）** |
| F. Rust `tray-icon` + `egui` | 安全、生态好 | 偏离 C++ 偏好；macOS 签名摩擦 | C++ 进度失败时的后备 |
| G. C++ 核心 + Rust HTTP/JSON FFI | 各取所长 | v1 双工具链成本 | 延后 |

### 5.1 语言与构建

- **语言：** **C++11**（`CMAKE_CXX_STANDARD 11`，`CMAKE_CXX_STANDARD_REQUIRED ON`）  
- **构建：** CMake ≥ 3.16（推荐 3.25），Ninja  
- **编译器：** MSVC 2019+ `/std:c++11`（或等价 VS 工具链），Apple Clang `-std=c++11`  
- **打包：** Win zip（主要更新单元）/ 可选后续 MSIX；macOS `.app` 打入 zip 或公证 DMG  
- **依赖（v1，优先静态或 vendor 合并源）：**
  - **线程：** POSIX **pthread** API
    - **Windows：** vendor **[pthreads4w](https://sourceforge.net/projects/pthreads4w/)**（pthreads-w32 谱系）；在体积允许时优先将 `pthread` **静态**链入主程序，避免单独 DLL
    - **macOS / Linux：** 系统 `libpthread`（无额外依赖）
  - **JSON：** [RapidJSON](https://github.com/Tencent/rapidjson)（头文件库，适配 C++11，配置级载荷足够快）。**不用 simdjson**（需 C++17+）。
  - **HTTP：** 优先平台原生 — WinHTTP / `NSURLSession`；若双后端成本更高可考虑 libcurl
  - **哈希：** 系统加密实现 SHA-256（BCrypt / CommonCrypto）— v1 校验无需额外加密库
  - **归档：** Win — 系统解压或 miniz 合并源处理 zip；macOS — 优先 zip-of-`.app` 或 `ditto` 应用
  - **文件系统：** 不用 `std::filesystem`；用薄封装 `core/fs` 包 Win32 / POSIX
  - **UI 面板：** 阶段 A 原生控件；若成本过高可阶段 B 引入 Dear ImGui（支持 C++11）
  - **日志：** 轻量写入用户数据目录

**C++11 可移植代码约定：**

| 使用 | 避免 |
|------|------|
| `unique_ptr` / `shared_ptr` / `move` | `std::optional` / `std::variant`（用辅助类型或指针） |
| **`pthread_t` / `pthread_mutex_t` / `pthread_cond_t`** | **`core/` 内的 `std::thread` / `std::mutex` / `std::condition_variable`** |
| `std::atomic`（无锁标志可用） | `std::filesystem` |
| `chrono`、lambda、range-`for` | `string_view`、`std::span` |
| `nullptr`、`override`、`= delete` | concepts / ranges / 协程 |
| `core/` 内裸 `CreateThread` / `_beginthreadex` | — 只用 pthread；平台 UI 线程除外 |

### 5.2 进程与线程模型

**进程**

- 正常运行单进程；单一 **UI 线程** 拥有托盘 / 面板 / 消息循环（Win：UI 线程 + `GetMessage`；macOS：main / `NSRunLoop`）。
- 网络、磁盘、（大）JSON 解析、**下载** 在 **pthread worker** 上执行。
- **应用更新** 可拉起短生命周期 **更新助手进程**，以便主进程退出后替换文件。
- v1 无长驻第二守护进程。

**pthread 布局（v1）**

```
UI 线程（OS）            worker pthread(s)           可选助手进程
──────────────          ─────────────────           ──────────────────────
托盘 / 菜单 / 面板        HttpClient 拉取             --apply-update
经平台封送回传 UI         写缓存                      替换文件 + 重启
                        SHA-256 / 暂存更新
```

| 原语 | 用途 |
|------|------|
| `pthread_create` / `join` 或分离 | 一个长生命周期 worker 或小池（起步：**1 worker + 任务队列**） |
| `pthread_mutex_t` | 保护共享模型 / 队列 |
| `pthread_cond_t` | 有任务时唤醒 worker；关闭时可等待空闲 |
| 线程局部存储 | 勿用于 UI 亲和；禁止在非 UI 线程碰 HWND/NSView |

**Windows 专项（pthreads-w32）**

- Vendor 至 `third_party/pthreads4w`（或等价路径）；CMake 在 `WIN32` 下链接，并按所选构建定义所需宏（如 `HAVE_STRUCT_TIMESPEC`）。
- 优先将静态库（上游命名如 `libpthreadVC3.lib`）链入应用；若动态 CRT 不匹配被迫用 DLL，须文档说明。
- 禁止在 pthread worker 中直接调用 Win32 UI API；用 `PostMessage` / 自定义队列封送到 UI 线程。
- 关闭顺序：发停止信号 → `pthread_cond_broadcast` → join workers → 再销毁托盘 HWND。

**macOS / Linux**

- 链接系统 pthread；可用薄 C++11 封装 `core/thread`（`Thread` / `Mutex` / `Cond`）包在 `pthread_*` 之上，封装须保持精简。

### 5.3 托盘与输入语义

| 输入 | 行为 |
|------|------|
| 左键 | 切换面板 |
| 右键 | 显示原生菜单（不切换面板） |
| 面板失焦 / Esc | 隐藏面板 |
| 双击 | 与左键相同（Win）；无必要不作特殊分支 |

macOS：使用 accessory / `LSUIElement`，不出现 Dock 图标。

### 5.4 面板定位

- 优先锚定 OS 暴露的托盘图标几何；否则靠近光标；钳制在工作区 / 可见屏幕内。
- HiDPI：正确处理 Win Per-Monitor V2 与 macOS `backingScaleFactor`。

### 5.5 配置与缓存

用户数据目录示例：

- Win：`%APPDATA%/VersionHub/`（最终名待定）
- macOS：`~/Library/Application Support/VersionHub/`

文件：

| 文件 | 用途 |
|------|------|
| `settings.json` | 端点 URL、轮询间隔、登录启动、`auto_update` |
| `cache/config.json` | 上次成功远程载荷 |
| `cache/meta.json` | ETag、fetched_at、状态 |
| `local_overrides.json` | 可选已装版本 / 隐藏条目 |
| `update/stage/` | 已下载包 + 校验通过标记 |
| `update/state.json` | pending / applying / 失败原因 |

拉取算法：

1. 有缓存 → 解析 → 立即展示。  
2. 带 ETag / If-Modified-Since 的条件 GET。  
3. 200 → 校验 `schema_version` → 原子替换缓存 → 通知 UI。  
4. 304 → 仅更新 `fetched_at`。  
5. 错误 → 保留缓存；面板页脚「上次同步：错误」。  
6. 配置解析成功后 → 将 `app.update` 交给 `UpdateCoordinator`。

### 5.6 JSON Schema 契约

- `schema_version` 为整数；客户端初期支持 `{1}`。
- 忽略未知字段。
- 缺少必需的 `groups` 数组或根非对象则拒绝。
- 条目 `action.type` v1 枚举：`url` | `path` | `none`。
- **v1 无 `shell` / `command` 动作**（见风险文档）。
- `app.update` 可选；缺失则隐藏自更新 UI。
- 包条目必须含 `os`、`arch`、`url`、`sha256`、`format`。

### 5.7 自更新设计

**范围边界：** 仅更新**本托盘二进制 / .app**。不下载、不安装面板目录中的工具。

**版本比较：** semver（`MAJOR.MINOR.PATCH`）；预发布标签可后续支持。

**通道：** v1 仅 `stable`；schema 预留 `beta`。

**流程：**

```
检查清单 → 有新版本？ → 提示 / 自动
    → 下载到 update/stage/
    → SHA-256 校验（失败 → 中止并删除暂存）
    → 写校验标记 + state=ready
    → 拉起更新助手（路径 + 重启参数）
    → 主进程干净退出
    → 助手替换安装树
    → 助手启动新二进制
    → 新进程清理暂存；清空 state
```

**Windows 应用：**

- 安装布局：便携目录，或 `%LOCALAPPDATA%/VersionHub/app/<ver>/` + 联接/`current`（优先版本目录以便回滚）。
- 助手：同签名的小体积 `updater.exe`（或以 `--apply-update=` 重启自身）。
- 主进程退出后再替换；重启参数 / 开机启动注册保持不变。

**macOS 应用：**

- 优先替换 `/Applications` 或用户选定位置的 `VersionHub.app`（首次运行记录安装路径）。
- 产物：含 `.app` 的公证 zip，或 DMG（DMG 更复杂 — **v1 优先 zip-of-app**）。
- 助手须尊重 SIP / 所有权；若安装目录只读给 root，应明确失败并提示「请移到用户可写位置」，禁止静默提权。

**强制更新：**

- 若 `app.min_client_version` > 运行版本：持续横幅；允许刷新 / 退出；默认仅警告，不硬锁死目录操作（除非产品策略另行要求）。

**签名策略（v1 最低要求）：**

| 层 | Windows | macOS |
|----|---------|-------|
| 传输 | HTTPS | HTTPS |
| 完整性 | 清单中的 SHA-256 | 清单中的 SHA-256 |
| OS 信任 | 分发构建 Authenticode | 公证 + staple |
| 应用级签名 | 可选 ed25519（P1） | 可选 ed25519（P1） |

**回滚：** 版本化安装目录保留上一构建，直至新版本成功运行 N 次会话（或始终保留一份上一版）。

### 5.8 安全边界

- 远程端点仅 HTTPS（本地开发可用设置开关例外允许 `http://127.0.0.1`）。
- `path` 动作必须为绝对路径；设置中可配置允许根目录白名单。
- v1 远程 JSON 不得触发任意脚本执行。
- 更新 URL 必须 HTTPS；可选主机白名单（与配置同源或设置中显式列表）。
- 无匹配 `sha256` 绝不应用。
- 证书锁定为 P2；v1 依赖系统 CA。

### 5.9 后续可能引入 Rust 的位置

仅当实测有明显收益：

| 模块 | 为何用 Rust | 集成方式 |
|------|-------------|----------|
| 归档解压 + 校验 | zip 边界情况的内存安全 | `cdylib` C API |
| Schema 迁移工具 | CLI 便利 | 独立二进制 |

除非解压 / zip 问题迫使 spike，v1 自更新路径保持**纯 C++**。

## 6. 仓库布局（提议）

```
tray_demo/
  docs/           SPEC、RFC、RISK
  include/tray_demo/
    plugin/       IAppModule
    panel/        IListPanelModel、面板宿主接口
    modules/demo/ 业务头（可选放 include）
  src/
    app/          main：平台绑定 + RegisterModule
    core/         框架：controller 分发、会话、设置、util
    modules/demo/ DemoModule + CatalogModel（业务）
    platform/win/ 托盘、面板宿主、WebView2、登录窗
    platform/mac/  macOS 桩（NSStatusItem 等待接）
    platform/linux/ Linux 桩（SNI / AppIndicator 等待接）
  server/
    internal/framework/  JWT、ACL、Module 接口
    internal/modules/    catalog、adminui
    internal/app/        Mount 装配
  third_party/    webview2、pthreads4w、…
```

**解耦约定：** C++ 登录属框架 `AuthModule`；业务只实现 `IAppModule` / `IListPanelModel`（动作前缀 `module_id.*`，`menu_order` 合并菜单）。Go 业务只实现 `framework.Module`，后台扩展经 `Deps.Admin.RegisterNav`。`AppController` 与 `internal/framework` 不含产品菜单/业务 handler，且 **framework 不 import modules**。 mac 平台当前为可编译桩。

## 8. 未决 RFC 问题

1. 面板列表用原生控件还是 Dear ImGui — M1 后限时（≤ 3 天）ImGui spike 再定。  
2. 统一 HTTP 抽象，还是仅 WinHTTP + NSURLSession。  
3. 产品显示名与 bundle ID。  
4. `installed_version` 由服务端还是客户端解析。  
5. Win 便携 zip vs 版本化 `%LOCALAPPDATA%` 更新布局。  
6. 应用级 ed25519：v1 强制，还是 P1（依赖 Authenticode/公证）。  
7. 长期坚持 C++11，或日后仅因更快 JSON 库（simdjson）经 RFC 升到 C++17。  
8. pthreads4w 静态 vs DLL；确认 Apache-2.0 构建（避免不合规使用旧 LGPL 包）。  

## 9. 建议

**采纳方案 E：** **C++11** 原生托盘应用，共享核心、RapidJSON、**全平台 pthread（Windows = pthreads-w32/pthreads4w）**、平台 HTTPS、类 Toolbox 浮动面板，以及**一等公民自更新流水线**。Linux 与 Rust 延后；明确**不以 MFC 作为跨平台基础**。**不要**把自更新扩展成通用工具安装器。
